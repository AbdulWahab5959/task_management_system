# Requirement

Use this template for `00-requirement.md`. Follow [the workflow guide](../README.md); in a task copy, link the guide as `../../README.md`. Replace guidance with task-specific facts and retain the original request and subsequent amendments.

## Title

State the requested outcome in a short title.

## Task ID

Use the unique ID in the task directory name.

## Task Level

Select Level 1 / Level 2 / Level 3 and explain the risk classification. Classify by affected behavior, not file count.

## Original User Request

Preserve the user's requirement as accurately as possible, with its date and source. Redact sensitive content explicitly. Keep technical recommendations separate; later investigation must not rewrite this request or silently expand it.

## Business Objective

Describe the business outcome, or mark it unknown when the user has not supplied one.

## User Objective

Identify the affected user or developer and the outcome they need.

## Expected Behavior

Describe observable behavior requested by the user. Label unresolved assumptions.

## Current Behavior

Record reported behavior and distinguish it from behavior already verified in the repository.

## Scope

List included behaviors and affected areas authorized by the request.

## Out of Scope

List explicit exclusions and adjacent work that is not authorized.

## Constraints

Record task-specific compatibility, environment, time, and implementation constraints. Reference applicable policy instead of duplicating it.

## Acceptance Criteria

Give each observable criterion a stable ID, such as AC-1, and a verification method. Preserve IDs through later artifacts.

## Known Risks

List known risks and whether investigation is needed to classify them.

## Human Decisions

Record outstanding decisions separately from confirmed decisions. For a confirmed decision, include who decided, when, and the source; do not treat a recommendation as approval.

## Status

Select DRAFT / INVESTIGATING / PLANNED / AWAITING APPROVAL / IMPLEMENTING / IN REVIEW / IN QA / COMPLETE / BLOCKED. Include the date and next action; completion requires the applicable review, QA, and evidence.

## Requirement Amendment

Append one dated entry per actual change; otherwise state None. Do not erase the original request.
